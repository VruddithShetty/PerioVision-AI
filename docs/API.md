# PerioVision AI: REST API

_Generated by `backend/scripts/generate_api_docs.py` from live calls against the app in demo mode. The machine-readable spec is `docs/openapi.json`, also served at `GET /api/docs`._

## Conventions

- **Base URL:** `http://127.0.0.1:5000` (the frontend dev server proxies `/api`).
- **Envelope:** every JSON response is `{"data": …, "meta": {…}, "error": null | {code, message, details}, "mode": "demo" | "live"}`.
- **Auth:** `POST /api/auth/login` returns a 15-minute access token; send it as `Authorization: Bearer <token>`. The refresh token is an httpOnly cookie used only by `POST /api/auth/refresh`.
- **Zero Trust:** every protected request re-checks token, server-side session, device, account state and the RBAC permission listed below. Routes without a permission are denied by default.
- **Errors:** 401 not authenticated, 403 not allowed, 404 not found (also used for records you may not see), 409 conflict (e.g. report before sign-off), 415 rejected upload, 422 validation (`error.details` lists fields), 429 rate limit.
- **Privacy:** patients appear in logs only as pseudonyms (`P-…`); radiographs and reports are stored AES-256-GCM encrypted.

## Endpoint index

| Method | Path | Permission | Summary |
|---|---|---|---|
| GET | `/api/admin/config` | admin:config | Thresholds, key IDs and signing status |
| GET | `/api/admin/users` | admin:users | List user accounts |
| POST | `/api/admin/users` | admin:users | Create a user account |
| PATCH | `/api/admin/users/{user_id}` | admin:users | Change a user's role or disable them |
| POST | `/api/admin/users/{user_id}/lock` | admin:users | Lock a user for a number of minutes |
| POST | `/api/analyses` | analysis:run | Run the full analysis pipeline on an upload |
| GET | `/api/analyses` | analysis:read | Recent analyses visible to you |
| GET | `/api/analyses/{analysis_id}` | analysis:read | Analysis detail: teeth, uncertainty, risk, review status |
| GET | `/api/analyses/{analysis_id}/image/{layer}` | analysis:read | Decrypted image layer (radiograph, annotated, gradcam) |
| POST | `/api/audit/anchor` | audit:verify | Publish (anchor) a Merkle root now |
| GET | `/api/audit/logs` | audit:read | Browse the tamper-evident audit log |
| GET | `/api/audit/verify` | audit:verify | Verify the hash chain and Merkle anchors |
| POST | `/api/auth/login` | public | Sign in with email and password (returns an access token or an MFA challenge) |
| POST | `/api/auth/logout` | self:manage | Sign out and revoke this session |
| GET | `/api/auth/me` | self:manage | Current user and their permissions |
| POST | `/api/auth/mfa` | public | Complete sign-in with a 6-digit TOTP code |
| POST | `/api/auth/mfa/confirm` | self:manage | Confirm TOTP enrolment with a code |
| POST | `/api/auth/mfa/disable` | self:manage | Turn TOTP off (needs a current code) |
| POST | `/api/auth/mfa/enroll` | self:manage | Start TOTP enrolment (QR code) |
| POST | `/api/auth/refresh` | public | Get a new access token from the refresh cookie (rotates it) |
| GET | `/api/auth/sessions` | self:manage | My active sessions |
| GET | `/api/dashboard` | self:manage | Role-aware dashboard numbers |
| GET | `/api/docs` | public | OpenAPI 3.0 description of this API. |
| GET | `/api/health` | public | Liveness and database check (no sensitive detail) |
| GET | `/api/models/metrics` | public | Held-out test metrics of the installed models, read from their metric files |
| GET | `/api/models/status` | model:read | Model files and signature status |
| GET | `/api/models/trust` | model:read | Calibration, flagged share and model integrity |
| GET | `/api/patients` | patient:read | List or search patients (exact name or pseudonym) |
| POST | `/api/patients` | patient:write | Create a patient (identity fields are encrypted) |
| GET | `/api/patients/{patient_id}` | patient:read | Patient detail with visit history |
| PATCH | `/api/patients/{patient_id}` | patient:write | Update patient details or clinical risk factors |
| GET | `/api/patients/{patient_id}/care-plan` | care:read | EFP step therapy, per-tooth prognosis, recall interval and referral suggestion. |
| POST | `/api/patients/{patient_id}/care-team` | admin:users | Add a clinician to a patient's care team |
| GET | `/api/patients/{patient_id}/perio-charts` | chart:read | All periodontal charts for a patient (newest first), each with computed indices. |
| POST | `/api/patients/{patient_id}/perio-charts` | chart:write | Save a six-point periodontal chart. |
| GET | `/api/patients/{patient_id}/progression` | analysis:read | Tooth-by-tooth progression across visits |
| POST | `/api/radiographs` | radiograph:upload | Upload a radiograph (upload guard + quality preview) |
| GET | `/api/recall` | care:read | Clinic-wide supportive-care recall list: who is due or overdue, ranked by risk. |
| POST | `/api/reports` | report:generate | Generate a signed PDF report (needs sign-off first) |
| GET | `/api/reports` | report:read | Signed reports visible to you |
| POST | `/api/reports/verify` | public | Public: verify an uploaded PDF |
| GET | `/api/reports/verify/{report_id}` | public | Public: verify a report by its ID (QR code) |
| GET | `/api/reports/{report_id}/download` | report:read | Download a report PDF |
| GET | `/api/review/queue` | review:read | Cases waiting for mandatory clinician review |
| POST | `/api/review/{analysis_id}` | review:signoff | Approve, correct or reject an analysis. Corrections are stored for future retraining. |
| GET | `/api/security-lab` | security_lab:run | List Security Lab attack simulations |
| POST | `/api/security-lab/run-all` | security_lab:run | Run every attack simulation |
| POST | `/api/security-lab/{scenario_id}/run` | security_lab:run | Run one attack simulation |
| GET | `/api/security/rbac-matrix` | self:manage | Role permission matrix |
| GET | `/api/security/sessions` | security:read | Active sessions of all users |
| GET | `/api/system/status` | self:manage | System status widget: DB, model signatures, audit chain, calibration |
